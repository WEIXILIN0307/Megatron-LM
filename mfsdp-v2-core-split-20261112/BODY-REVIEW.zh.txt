RFC / PR 正文审查与修订

本次组织为三个 PR：两个独立的 eager 正确性修复，以及现有 #9112 基础 graph 集成。
三个 PR 的测试与实现分别归属；主 PR 的 source diff 不包含两项前置修复，明确其
合入依赖，并将组合源码版本与独立 PR head 区分。#7582、细粒度桥接和 EP 重排不提交。

发现并修正的主要描述问题：
1. 旧正文对 recoverable Python failure 的表述过宽。新正文只承诺测试过的 MCore
   自有失败点；明确 TE 2.20.2 warmup 临时 hook 清理属于独立依赖，必要时重启。
2. 旧的 AG 普通/专家 mesh 归属可能混入 prefetch 发起者。最终 trace 对 AG 合并归属，
   RS 按实际 reducing unit 归属，不用调用者名称推断目标 process group。
3. 图外 FSDP kernel 与图计算并发，不等于 EP token A2A 被有效隐藏，也不等于稳定加速。
   新正文将三个结论分开，原始任务不追加 EP 隐藏或固定加速比例门槛。
4. 旧完整分支的四卡细粒度结果不能直接用于收窄后的基础集成。最终源码重新运行
   普通模块路径的两卡、四卡回归，并使用明确标注的真实文本 MoE proxy。
5. 大模型 loss 相同不足以证明全部训练状态一致。真实文本比较只对实际采样的
   第 4、12 步声明完整逻辑分片的逐张量摘要一致，不外推未观测迭代或收敛。
6. 保留 full BF16 compute buffer 的内存代价按现有 FSDP unit 解释；不声称新建第二份
   参数存储，也不把已经常驻的复制 buffer 说成额外新增分配。
7. 人工作者逐行审查勾选项保持未勾选，PR 保持 draft；不声称完整 upstream CI 已通过。

四卡首次失败及定位：删除 graph 后的内存断言每轮增加 17,039,360 字节。独立观测器
仅在原测量位置清理 cuBLAS 工作区后，四个 rank 的三轮 FSDP 剩余分配各自完全一致，
数值对照通过。最终测试复用既有 test_memory.py 的缓存控制方法，不放宽阈值，
不删除断言，不在生产路径加入全局缓存清理。原始失败日志及诊断数据均保留。
